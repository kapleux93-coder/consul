# Consul — бэкенд

Сервер для мини-аппа `../consul.html`. Подключает Telegram-бота владельца, отвечает
его клиентам через **Groq** и передаёт диалог живому менеджеру, когда так решает
модель. Node 18+, внешних зависимостей нет.

## Быстрый старт — три шага

```bash
cd consul-server
cp .env.example .env
```

**1. Создайте бота.** В Telegram: @BotFather → `/newbot` → имя и username.
Токен впишите в `.env` в строку `BOT_TOKEN=`.

**2. Возьмите ключ Groq** на https://console.groq.com/keys и впишите в `GROQ_API_KEY=`.

**3. Настройте и запустите.**

```bash
npm run setup   # username бота, кнопка меню, команды, описание, вебхук
npm start
```

`npm run setup` делает всё, что иначе пришлось бы кликать в BotFather, и его можно
повторять после каждого деплоя. При старте сервер печатает, что настроено, а что нет —
если чего-то не хватает, он скажет прямо.

Посмотреть, какие модели доступны вашему ключу: `npm run models`.

### Совсем без ключей — посмотреть приложение

```bash
node mock-groq.js 8099 &
ALLOW_INSECURE_AUTH=1 GROQ_API_KEY=dev GROQ_BASE_URL=http://127.0.0.1:8099/v1 node server.js
```

`ALLOW_INSECURE_AUTH=1` подставляет фиктивный initData, чтобы мини-апп открылся вне
Telegram, и включает `POST /api/dev/incoming` — имитацию сообщения от клиента.
**На публичном адресе сервер с этой переменной не стартует**: она отключает проверку
подписи, то есть открывает чужие кабинеты.

## Как это устроено

```
клиент → бот владельца → вебхук/polling → server.js
                                            ├─ limits.js  квоты и частота
                                            ├─ ai.js ──→ Groq (chat completions)
                                            ├─ extract.js  PDF / DOCX / XLSX → текст
                                            ├─ store.js (data/store.json)
                                            └─ SSE → мини-апп владельца
                                                 └─ бот Consul → уведомление менеджеру
```

Два бота — это важно:

| Бот | Чей токен | Зачем |
|---|---|---|
| **Consul** (платформенный) | ваш, в `BOT_TOKEN` | из него открывают мини-апп; он же шлёт владельцу и менеджерам уведомления о передачах |
| **Бот клиента** | вводит владелец в онбординге, хранится зашифрованным | с ним переписываются покупатели, от его имени отвечает AI |

## Деньги и лимиты

Ключ Groq один на весь сервис, платит за него владелец сервера. Поэтому расход
ограничен с трёх сторон, и все пороги настраиваются в `.env`:

| Лимит | По умолчанию | Что делает при достижении |
|---|---|---|
| `LIMIT_DAILY_AI` | 300 ответов в сутки на кабинет | диалог уходит менеджеру, владельцу приходит уведомление |
| `LIMIT_DAILY_GLOBAL` | 5000 ответов в сутки на сервис | то же, но для всех кабинетов сразу |
| `LIMIT_CHAT_PER_MIN` | 6 сообщений в минуту от одного клиента | лишние сообщения не доходят до модели |
| `LIMIT_API_PER_MIN` | 120 запросов в минуту от пользователя | мини-апп получает 429 |
| `LIMIT_KB_CHARS` | 300 тыс. знаков базы знаний на кабинет | новый источник не принимается |

Упереться в лимит не значит замолчать: клиент всегда получает ответ, просто
диалог переходит к человеку. Расход по токенам видно в мини-аппе (More → Billing)
и целиком — в `POST /api/admin/stats`, если ваш Telegram id указан в `ADMIN_IDS`.

## Что именно делает AI

Каждый ответ — один вызов Groq в JSON-режиме. Модель возвращает сразу и текст клиенту,
и решение звать человека, и обновление карточки клиента:

```json
{ "reply": "…", "handoff": false, "reason": "", "stage": "interested",
  "interest": "панели для офиса", "summary": "…", "contact": "" }
```

Системный промпт собирается из кабинета владельца: описание компании, стиль и длина
ответов, тумблеры «AI может сам», запрещённые темы, правила передачи человеку и куски
базы знаний, отобранные под конкретный вопрос. Переключатели в мини-аппе — не
украшение: они меняют текст промпта, а значит и поведение бота.

Модели явно запрещено выдумывать цены, сроки и наличие. **Если Groq недоступен,
ключа нет или исчерпана квота — бот не сочиняет ответ**, а честно пишет «подключаю
менеджера» и переводит диалог в статус «нужен человек».

## Голос компании

Стиль ответов можно не выбирать из трёх кнопок, а снять с того, как владелец
пишет на самом деле. В мини-аппе (AI Settings → «Научить AI писать как вы»)
роли переворачиваются: **модель играет покупателя, а владелец отвечает как
продавец**. По трём-четырём его репликам второй запрос к модели вытаскивает
манеру — длину, обращение на «вы» или «ты», смайлы, привычные обороты —
и превращает её в инструкцию для бота.

Профиль сначала показывается владельцу и применяется только по кнопке.
После применения он уходит в системный промпт отдельным блоком «ГОЛОС
КОМПАНИИ» вместе с парой дословных примеров, а `style` и `lengthVal`
подставляются автоматически. Снять — «Убрать голос» там же.

| Метод | Что делает |
|---|---|
| `POST /api/style/scenarios` | список сценариев: выбирает товар, торгуется, недоволен, опт |
| `POST /api/style/next` | следующая реплика «клиента» с учётом истории |
| `POST /api/style/analyze` | разбор манеры по репликам владельца, минимум три |
| `POST /api/style/apply` | применить разобранный профиль к боту |
| `POST /api/style/forget` | снять голос, вернуться к простым настройкам |

## Как бот продаёт

Отвечать на вопросы и продавать — разные ремёсла. Второе включается тумблером
«Активно продавать» в AI Settings и меняет и промпт, и поведение.

**Выясняет, потом предлагает.** Один-два вопроса по существу — для кого, сколько
человек, когда нужно — и дальше ОДНА рекомендация вместо каталога. Выбор
объясняется через задачу клиента, а не через характеристики: не «парная 6 м²»,
а «для двоих в самый раз».

**Всегда даёт следующий шаг.** Не «остались вопросы?», а конкретное и лёгкое:
прислать фото, посчитать доставку в город, забронировать срок.

**Работает с возражениями.** «Дорого» — не сбрасывать цену, а спросить, с чем
сравнивают, или предложить вариант дешевле. «Подумаю» — выяснить, что осталось
решить. «Дешевле у других» — не обесценивать конкурента, а назвать, что входит.
Прямой отказ — принять и не уговаривать дважды.

**Не врёт ради сделки.** Запрещено выдумывать срочность («осталось два места»),
давить после отказа и продавать то, что человеку не подходит.

После каждого ответа модель отдаёт ещё три поля, и они видны владельцу:
температуру клиента (в Inbox — метка «🔥 горячий»), предложенный следующий шаг
и возражение, которое мешает сделке.

### Возврат замолчавших

Больше всего сделок теряется не на возражении, а в тишине: человек спросил цену,
задумался и забыл. `followup.js` раз в пять минут обходит диалоги и пишет **один
раз** тем, кто пропал на середине разговора.

Правил, когда писать НЕЛЬЗЯ, больше, чем самой отправки: только если последним
говорил бот, клиент успел сказать хотя бы пару реплик, не отказался, диалог не
забрал человек, AI не на паузе, прошло больше `followUpMin` (45 минут по
умолчанию) и меньше суток, сейчас не тихие часы по времени бизнеса и есть остаток
дневной квоты. Если владелец забирает диалог, напоминание отменяется.

Всё настраивается в AI Settings: порог, ночное окно и сам тумблер.

## Чтобы бот не выдавал в себе бота

Отвечать правильно мало — надо ещё вести себя как человек. `human.js` отвечает
за поведение во времени, промпт в `ai.js` — за речь.

**Не отвечает мгновенно.** Пауза складывается из «прочитал и подумал» (1,2–2,6 с)
и скорости печати (22 знака в секунду), потолок 7 секунд на реплику. Время,
которое уже потратила модель, из паузы вычитается — иначе клиент ждал бы дважды.
Индикатор «печатает» в Telegram гаснет через 5 секунд, поэтому обновляется всю
паузу.

**Не шлёт стену текста.** Модель ставит пустую строку там, где живой человек
нажал бы «отправить», и ответ уходит двумя-тремя репликами с паузой между ними.
Если разрывов нет, а текст длинный, он режется по границе предложения.

**Не отвечает на каждую строчку.** Клиент часто пишет очередью: «здравствуйте»,
«а бани есть», «недорого». Бот ждёт 2,5 секунды тишины и отвечает на всю очередь
разом — как человек, который дочитал и ответил один раз. Если владелец успел
забрать диалог за это время, назначенный ответ отменяется.

**Говорит по-человечески.** Промпт запрещает канцелярит («уточните, пожалуйста»,
«данный товар», «осуществляется»), требует отвечать на вопрос в первом же
предложении, подстраиваться под клиента по длине и обращению, не заканчивать
каждое сообщение вопросом и признавать раздражение прежде, чем решать проблему.

Владелец может выключить это в AI Settings → «Вести себя как человек», если
хочет машинную скорость. Отключается и глобально: `HUMANIZE=0`.

Пороги настраиваются: `HUMAN_THINK_MIN_MS`, `HUMAN_THINK_MAX_MS`,
`HUMAN_CHARS_PER_SEC`, `HUMAN_MAX_DELAY_MS`, `HUMAN_BURST_MS`.

## Файлы в базе знаний

`extract.js` читает PDF, DOCX, XLSX, CSV, TXT и HTML без единой зависимости
(zlib из стандартной библиотеки).

PDF разбирается по-настоящему, а не побайтово. Современные файлы из InDesign,
Word и 1С используют подмножества шрифтов с произвольными кодами: байт `0x03`
может означать любую букву. Такой текст читается только по таблице `/ToUnicode`,
которую PDF несёт рядом со шрифтом — парсер её находит и применяет, включая
случай, когда объекты упакованы в сжатый поток (`ObjStm`, PDF 1.5+). Если
таблицы нет, откатываемся к побайтовому чтению с распознаванием CP1251.

Чего он не сделает:

* **Сканы.** В PDF из фотографий нет текстового слоя — файл отклоняется с
  понятным сообщением, а не кладётся в базу пустым.
* **Файлы с паролем.** Отклоняются сразу, до разбора.
* **Совсем экзотические шрифты.** Если вместо букв всё же вышел мусор, срабатывает
  `looksLikeText`: доля букв, доля гласных и наличие обычных слов. Мусор в базе
  знаний хуже пустой базы — на нём модель начинает выдумывать.

В любом случае остаётся рабочий путь, и приложение предлагает его прямо в момент
отказа: вставить текст руками или дать ссылку на страницу сайта.

## API

Все методы, кроме `/health` и вебхуков, требуют заголовок `x-init-data` с Telegram initData.

| Метод | Что делает |
|---|---|
| `POST /api/state` | всё состояние кабинета (без секретов) |
| `POST /api/bot/connect` / `disconnect` | подключить/отключить бота владельца, ставит вебхук |
| `POST /api/biz`, `/api/ai`, `/api/step`, `/api/onboarded` | настройки компании и AI |
| `POST /api/knowledge/add`, `/remove`, `/import`, `/upload` | база знаний; `upload` принимает файл сырым телом, имя в `x-filename` |
| `POST /api/team/invite`, `/remove`, `/dept`, `/api/depts/add` | команда; `invite` отдаёт ссылку-приглашение |
| `POST /api/ai/test` | тестовый чат из онбординга |
| `POST /api/dialog/send`, `/takeover`, `/return`, `/read`, `/note` | работа с диалогом |
| `POST /api/channel/post` | сгенерировать пост для канала |
| `POST /api/notify/check` | может ли бот написать владельцу (иначе уведомления о передачах молча не придут) |
| `POST /api/account/delete` | удалить кабинет и все данные, нужен `confirm: "УДАЛИТЬ"` |
| `POST /api/diag` | что настроено: модель, режим приёма, квоты, предупреждения |
| `POST /api/admin/stats` | сводка по всем кабинетам, только для `ADMIN_IDS` |
| `GET /api/stream` | SSE: новые сообщения и смены статуса |
| `POST /tg/<secret>` | вебхук бота владельца |
| `GET /health` | проверка живости |

## Передача менеджеру

Менеджеры не получают уведомления «по username» — Telegram так не умеет. Владелец
нажимает «Добавить менеджера», получает ссылку `t.me/<бот>?start=join_<код>`,
менеджер её открывает — и с этого момента получает переданные диалоги в личку.
Пока он не нажал ссылку, в списке команды он помечен как «ждёт подтверждения».
В уведомлении есть ссылка, открывающая мини-апп сразу на нужном диалоге.

Владелец получает уведомления всегда.

## Что происходит, когда что-то ломается

| Ситуация | Поведение |
|---|---|
| Groq недоступен или упала квота | клиент получает «подключаю менеджера», диалог → «нужен человек» |
| Клиент заблокировал бота | диалог помечается закрытым, обработка не падает |
| Токен бота отозвали в BotFather | бот отключается, владельцу приходит уведомление с инструкцией |
| Ответ длиннее 4096 знаков | режется по абзацам и отправляется несколькими сообщениями |
| Модель вернула не JSON | берём сырой текст, если он похож на ответ; иначе зовём человека |
| Владелец не нажимал Start у бота Consul | в приложении баннер: иначе уведомления о передачах не дойдут |
| Пропала связь с сервером | в приложении баннер, а по возвращении состояние дозагружается само |

## Данные

Всё в `data/store.json`: кабинеты, диалоги, база знаний. Токены ботов зашифрованы
AES-256-GCM ключом из `CONSUL_ENC_KEY` (или `data/.enc-key`, если переменной нет).
Файл — нормально для одного инстанса; для нескольких воркеров замените `store.js`
на БД, интерфейс там узкий (`get/save/find`).

**Резервные копии** делаются в `data/backups/` раз в сутки и через 10 минут после
первого запуска, хранятся последние 7 (`BACKUP_KEEP`). Повреждённый стор копию не
вытесняет — иначе одна неудачная запись стёрла бы последнее хорошее состояние.

**Удаление данных.** Владелец может стереть кабинет целиком из More → «Удалить
кабинет и все данные»: диалоги, база знаний, настройки и токен бота удаляются,
вебхук снимается. Подтверждение — ввод слова УДАЛИТЬ.

История диалога обрезается до 300 сообщений, в промпт уходят последние 14.

## Куда деплоить

Приложению нужен обычный Linux с диском и процесс, который не засыпает.
Serverless (Vercel, Netlify) не подходит: нет ни диска, ни долгоживущего
процесса для SSE и опроса Telegram.

**Ключевая деталь: боту публичный адрес не нужен.** Без `PUBLIC_URL` сервер
сам опрашивает Telegram, клиенты пишут и получают ответы. Адрес нужен только
чтобы открывать панель владельца из Telegram. Поэтому бесплатный вариант —
не костыль, а рабочая схема.

| Вариант | Цена | Когда подходит |
|---|---|---|
| Свой Mac или мини-ПК + ngrok | бесплатно | старт, первые пользователи |
| Любой VPS (Timeweb, Selectel, aeza, Hetzner) | 200–400 ₽/мес | боевой запуск |
| Render | ~$7/мес | если уже есть аккаунт и зарубежная карта |

### Бесплатно и без туннеля: панель на localhost

Самый дешёвый рабочий вариант, если нет ни карты, ни домена.

```bash
cp .env.example .env      # вписать GROQ_API_KEY и BOT_TOKEN
npm run local
```

Панель открывается в браузере на http://localhost:8080. Клиенты пишут вашему
боту и получают настоящие ответы: сообщения забираются опросом Telegram,
публичный адрес для этого не нужен. Уведомления о переданных диалогах
приходят вам в Telegram как обычно.

Режим включает `ALLOW_INSECURE_AUTH` — проверки подписи Telegram нет, потому
что панель открыта не из Telegram. Поэтому сервер слушает **только 127.0.0.1**:
из сети, даже с телефона по своему же Wi-Fi, панель недоступна. Это не
настройка, а поведение по умолчанию — иначе диалоги увидел бы любой сосед по
кофейне.

Чего нет: панели внутри Telegram и доступа с телефона, и менеджеры не смогут
открыть кабинет со своих устройств. Когда это понадобится — нужен публичный
адрес, то есть туннель с постоянным доменом или VPS ниже.

### Бесплатно, на своём компьютере

Нужны `brew install node ngrok`, регистрация на ngrok.com (без карты) и
бесплатный статический поддомен из панели ngrok → Domains.

```bash
ngrok config add-authtoken <ваш токен>
cp consul-server/.env.example consul-server/.env   # вписать GROQ_API_KEY и BOT_TOKEN
bash deploy/free-macos.sh ваш-поддомен.ngrok-free.app
```

Скрипт ставит сервер и туннель фоновыми службами launchd: поднимаются после
перезагрузки, перезапускаются при падении. Он же выставляет `FORCE_POLLING=1` —
адрес есть, но сообщения всё равно забираются опросом. Это важно: после сна
ноутбука вебхуки теряются навсегда, а опрос восстанавливается сам, и сообщения
клиентов не пропадают.

Пока Mac спит, панель недоступна, но диалоги не теряются — бот разберёт их,
как только машина проснётся.

### На VPS

Нужен домен с A-записью на IP сервера: Telegram открывает мини-апп только по
https с настоящим сертификатом.

```bash
sudo bash deploy/install.sh consul.example.com
```

Ставит Node и Caddy, заводит отдельного пользователя, кладёт код в
`/opt/consul`, данные в `/var/lib/consul`, поднимает systemd-сервис и выпускает
сертификат. Повторный запуск безопасен. Обновление — `sudo bash
/opt/consul/deploy/update.sh`.

## Деплой на Render бесплатно

Работает по-настоящему: публичный https-адрес есть, мини-апп открывается из
Telegram, клиенты получают ответы. Держится на двух вещах, обе обязательны.

**База во внешнем Redis.** Free-план не даёт диска, файловая система стирается
при каждом перезапуске. Заведите базу на upstash.com (256 МБ и 500 тысяч команд
в месяц, карта не нужна), во вкладке REST API скопируйте `UPSTASH_REDIS_REST_URL`
и `UPSTASH_REDIS_REST_TOKEN`. Без них сервер откажется стартовать — терять чужих
подключённых ботов молча нельзя. Вся база держится в памяти и пишется целиком
раз в секунду, поэтому 50 правок подряд превращаются в одну команду.

**Пингер против засыпания.** Инстанс засыпает через 15 минут тишины, а спящий
сервис не опрашивает Telegram. Заведите бесплатную проверку на cron-job.org или
uptimerobot.com: раз в 10 минут дёргать `https://ваш-адрес.onrender.com/health`.
В месяце ~730 часов, бесплатных 750 — на круглосуточную работу одного сервиса
хватает, на второй уже нет.

Порядок:

1. New → **Blueprint**, репозиторий, Blueprint Path: `render-free.yaml`
2. Вписать `GROQ_API_KEY`, `BOT_TOKEN`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`
3. После деплоя в Shell: `npm run setup`, оттуда же взять `BOT_USERNAME` в переменные
4. Настроить пингер на `/health`
5. В @BotFather указать Web App URL — адрес сервиса

`FORCE_POLLING` включён намеренно: если инстанс всё же уснёт, сообщения
накопятся в очереди Telegram и разберутся при пробуждении. С вебхуками они
уходили бы в спящий сервис и терялись.

## Деплой на Render

1. New → **Blueprint**, выберите репозиторий. `render.yaml` лежит в корне и
   подхватится сам; на подпапку с сервером указывает `rootDir` внутри него.
   Поля «Root Directory» в интерфейсе Blueprint нет — оно только в обычном
   Web Service.
2. В панели задайте `GROQ_API_KEY` и `BOT_TOKEN`. `CONSUL_ENC_KEY` и
   `PLATFORM_WEBHOOK_SECRET` Render сгенерирует сам, `PUBLIC_URL` подставится
   из `RENDER_EXTERNAL_URL`.
3. После первого деплоя в Shell сервиса: `npm run setup`.

4. Задайте в панели ещё две переменные, которые `setup` подскажет в выводе:
   `BOT_USERNAME` и `PLATFORM_WEBHOOK_SECRET`. На хостинге файловая система
   эфемерная, поэтому в `.env` их писать бесполезно — переживут только панель.

План берётся из `render.yaml` и пересинхронизируется при каждом обновлении —
меняйте его в файле, а не в панели, иначе тариф откатится обратно.

**Free-план не подойдёт.** На нём Render не даёт постоянный диск, а без диска
после каждого деплоя пропадут кабинеты и ключ шифрования. Плюс инстанс засыпает
без активности и теряет часть сообщений. В `render.yaml` стоит `starter`.

Диск обязателен — на нём кабинеты пользователей и ключ шифрования. Потеряете
диск — все владельцы будут подключать ботов заново.
